## Bugs caught during the gate

- **D4, argument order.** `battle_director.gd`'s `_run_corpse_fade()` used `tween_method(Callable(self, "_set_corpse_alpha").bind(c), ...)`. `Tween.tween_method` calls the callable with the tweened value as the leading positional argument and appends `.bind()`'s arguments after it, so the actual call was `_set_corpse_alpha(alpha_value, c)` — but the function was declared `_set_corpse_alpha(c: Combatant, alpha: float)`, backwards, and its body called `CelMaterials.set_alpha_on(c.rig, alpha)` against a `set_alpha_on(value: float, root: Node)` signature, also backwards. Caught via `get_editor_errors` during `play_scene` (two `SCRIPT ERROR`s on the first corpse fade). Fixed by reordering the parameter list to `(alpha: float, c: Combatant)` and the internal call to `set_alpha_on(alpha, c.rig)`, matching the existing (correct) usage elsewhere in the same file.
- **D4, rush deadlock.** `_run_corpse_fade()`'s hold-phase used a boolean `corpse_rushed` meta flag to let a superseded slow-fade coroutine detect it was overtaken and bail out. `begin_corpse_cleanup()` set that same flag to `true` *before* launching its own rush coroutine through the identical function — so the rush coroutine's own hold-phase check saw the flag it had just set, concluded it too had been superseded, and returned without ever creating the fade tween or calling `_finish_corpse()`. Result: `_pending_corpse_fades` never reached zero, `await_corpse_cleanup()` never resolved, and the run stalled in `COMBAT` state forever once both enemies in an encounter were dead. Caught live: killed both enemies in encounter 0 via the `Debug` harness, watched `run_state` stay at `3` (COMBAT) indefinitely and `BattleDirector._pending_corpse_fades` stay at `2` with the game screenshot never advancing to travel. Fixed by replacing the boolean with a per-corpse generation counter (`corpse_gen` meta): every call to `_run_corpse_fade()` (slow or rush) captures the corpse's generation at launch and checks it's still current after each await; `begin_corpse_cleanup()` bumps the generation before starting its own rush call, which invalidates only the *older* in-flight coroutine, not itself. Re-verified after the fix: a fresh run progressed on its own from encounter 0 through travel, loot, and into encounter 3's shop with no manual intervention needed beyond killing enemies to speed up the observation.
- **F4, coin glyphs didn't render.** `add_node`'s `properties` dict included `"script": "res://scripts/console/coin_glyph.gd"`, but the tool does not apply the special `script` property through that parameter — only regular exported vars. All four newly-added `CoinGlyph` nodes (shop header, buy card, sell button) ended up as bare, scriptless `Control`s: no `_draw()`, so nothing rendered, confirmed by `get_game_node_properties` showing no `radius` property on the node (i.e. no script attached) and a shop screenshot with plain numbers and no coins. Fixed with `attach_script` on all four nodes, followed by `update_property` to set each one's `radius` (16 / 15 / 13) since the property write in the original `add_node` call was silently dropped along with the script.
